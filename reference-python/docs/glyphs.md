# 手绘汉字

**写字画骨架，不画轮廓。**

每一笔是一条**中心线**，笔的粗细由 `stroke-width` 撑出来。别去描字的外框 ——
描出来是「字的形状」，不是「写出来的字」。

## 规格

| 项目 | 规范 |
|---|---|
| viewBox | `0 0 64 64`，一字一格 |
| stroke-width | `2.8` |
| 字面范围 | 7–57，字要撑住格子 |
| 抖动 | `"amp": 0.65`（≈ 24 网格上的 0.22）**每一笔都要写** |
| 线重 | `stroke-width 2.8` 打底，单笔可以用 `"w"` 提按，**0.85–1.15**（见下） |
| 尺寸下限 | **44px**。30px 起复杂字开始糊，20px 只剩一团 |
| 字形 | **一律简体**（见/门/画，不是 見/門/畫） |

### 为什么抖动要压到 0.65

字比图形更不经抖。「口」抖散了就不是字了，而歪掉的图形还是那个图形。
**这是唯一一个必须逐笔写 `amp` 的场景。**

### 为什么尺寸下限是 44px

这支笔画一般图形 15px 还立得住，汉字要 44px —— 笔画密度差太多。
「情」有 11 笔挤在同一个 64 格里，而一枚普通图形的中位数是 2 个元素。
**用在正文尺寸上就别用这支笔**，老老实实排字。

### 逐笔线重：提按

一个字之内横细竖粗是**对的** —— 真手写有提按。
（这一条是汉字独有的：画图形时统一线重不能破，写字可以破。）几何里逐笔写：

```json
{"t": "path", "d": "M11 28 H53", "amp": 0.65, "w": 0.92}
```

| | 值 | 为什么 |
|---|---|---|
| 范围 | **0.85–1.15** | 再宽就不是提按，是两套线重混在一个字里 |
| 下限硬边界 | 44px 上不细过 **1.6px** | 2.8 × 0.85 = 2.38 单位，在 44px 上正好是 1.64px —— 卡着门槛。整组 `sw` 已经调轻过（wordmark 那种 2.4）就别再用 `w` 压细，也别再往 44px 那一档放：portfolio 那 14 张标题一个 `w` 都没用 |
| 该压细的 | 横、短撇、点 | 手写里起收快的笔画自然细 |
| 该留粗的 | 竖、竖钩、捺 | 承重的笔画，压细了字会散 |

**一笔之内变粗细做不到，也别试。** 那要把描边转成轮廓填充，
圆头笔锋、收笔越位、round join 整套都得重写 —— 换来的东西不值这个价。

**别拿 `w` 去救糊掉的字。** 糊了是骨架的问题（笔画太密、结构不对），
加粗只会更糊。回去删笔画或者放大结构。

## 转折必须自带半径

横折、竖钩、横折钩这些是汉字的骨头，全部走 `Q`：

```
横折      M31 36 H48 Q50.5 36 50.5 38.5 V52        r ≈ 2.5
竖钩      M45 21 V46 Q45 50 41 49.5                钩要甩出去，不是拐个弯
竖弯钩    M38 28 V48 Q38 55 44.5 55 Q49.5 55 50.5 49   两段 Q：先弯平，再挑起
横撇      M21 16 H35 Q37.4 16 36.2 19.2 C32 30 ...     折完接曲线
```

**钩不够挑就不是钩。** 收笔那一段要明显往回上方甩 —— 「心」的卧钩尾巴要抬起
7–9 个单位，抬不够整个字读成一个碗。

## 排一行字

下面这套规矩有一份实现：`scripts/row.py`（摆正 / 逐字大小 / 相邻差值 / 边界断言）。
编辑器底下那条行预览就是跑的它 —— 改完一个字立刻能看见它排进一行里是什么样，
不用另外拼一张图。**新写排版代码之前先看那份，别再实现一遍。**

### 1. 一字一格，格子等宽

每个字自己占一个 64 格，横向 `translate(i*64, 0)`。**格子等宽，格子里的字不等大**
（下一条）—— 但别去改格宽，改了字距就乱。

### 2. 逐字大小（比抖动更要紧的一条）

每个字都是照着 7–57 的字面画满的，所以**不摇大小就是一版字帖**：
线抖得再像手绘，五个字一样大、一样满，一眼还是排出来的。抖动只换了线的样子，
大小才换得掉「字是一个一个写下去的」这件事。

```
逐字 scale       ±9%      看得出来，又不至于像排错了
相邻两个字       至少差 3.5%   撞了就换个盐重摇（随机数会连着给两个相近值）
再各自压扁抻长    ±3.5%    宽高反着走（sx=1+f, sy=1-f），面积不变，字才不会忽胖忽瘦
横向也浮一点      ±1.1     光有竖向位移，格线还是看得出来
```

**缩放要绕字自己的中心做**（汉字绕字面中心、拉丁绕基线），
绕格子原点缩会把字甩到格子一角。

小尺寸的标题（显示 40px 上下）把幅度收到 0.6 倍再用：整档 ±9% 会让最小的那个字
掉到糊字的门槛以下。**幅度是跟着显示尺寸调的，不是一个常数。**

### 3. 随机数要过一次雪崩混合

逐字的大小/位移都得可复现，于是很容易写成 `(i*61 + seed*23) % 9` 这种式子 ——
**不行**：逐字取模走出来的是一条等差的阶梯，读下来是「小中大小中大」的规律，
比不抖还假。

换成哈希也**只对一半**：FNV 只乘一遍的话，输入是一两个小整数时 `i` 加一只把结果
推动百分之零点几，一行字的大小还是一条缓坡（实测 0.936 / 0.945 / 1.024，
前两个字肉眼一样大）。每一轮后面跟一次雪崩混合（murmur3 的收尾三步）才算数：

```python
def rnd(*key):                      # 0–1，同一份文案永远抖成同一个样子
    h = 2166136261
    for k in key:
        h = ((h ^ (int(k) & 0xFFFFFFFF)) * 16777619) & 0xFFFFFFFF
        h ^= h >> 16; h = (h * 0x85EBCA6B) & 0xFFFFFFFF
        h ^= h >> 13; h = (h * 0xC2B2AE35) & 0xFFFFFFFF
        h ^= h >> 16
    return h / 0xFFFFFFFF
```

摇完把一行的数值打印出来看一眼再收工 —— 相邻两个数差多少，比渲染图更早暴露问题。

### 全局种子与单字种子

种子不是“完全随机”的开关，而是确定性随机的输入：同一份字库、同一句文字和同一个
全局种子，会得到同一版大小、位置、骨架重写和线条抖动。换全局种子会重新计算整句；
保存它就能复用这一版。

编辑器里还可以给某个内部字形设置 `glyphSeeds`（例如 `露2: 777`）。它只替换这个
字形自己的随机输入，其他字的几何不跟着变；同一个字出现多次时，行预览仍会按出现位置
分别重写。没有局部种子的字继续跟随全局种子；编辑器开启「跟随全局」时会暂时停用
局部覆盖，但保留上一次的单字种子，再次关闭跟随即可恢复。

### 4. 先摆正，再抖

**排版这一层要的是「写偏了」，不是「画偏了」。** 字库里难免有画得偏左偏下的字
（实测「刀」的字面中心在 x=27、「不」在 y=38，排进一行里就是它自己缩在角上），
这种偏心和手写的随机不一样：它每次出现都偏同一边，看着像素材没对齐。

做法：排之前按字面框把字**拉回格子中央**，留一个死区（1.5）不动、拉回量也封顶
（5），刻意的偏心和标点（，？～）不参与。**摆正之后再叠大小和抖动** ——
手气要来自抖动那一层，是可控的；来自没摆正的字是不可控的。

### 5. 字能被写大之后，PAD 要量不能靠看

`viewBox` 的留白原来只要够放越位的笔锋（5 就够），一旦逐字放大，它变成
「够不够放最大的那个字」。渲出来看有没有被切是查不干净的 —— 切掉的往往正好是
最长那一钩，不并排比对根本看不出来。

把每个字的 transform 在代码里算一遍（旋转+缩放后的实际坐标），对着 viewBox
边界断言，越界直接报错。这条检查还会在**以后新加一个更宽的字**时替你挡一次。

### 一个字的 transform 就这一串

顺序不能换：**先摆正（内层 translate），再缩放，再倾斜，最后落到格子里。**

```python
# 汉字：ax/ay = 摆正后的字面中心；cx/cy = 格子中心 + 逐字位移
f = jitter(i, seed, 91, amp=0.035)
sx, sy = s * (1 + f), s * (1 - f)          # s 来自逐字大小
f'translate({cx} {cy}) rotate({rot}) scale({sx} {sy}) translate({-ax} {-ay})'

# 拉丁：支点在基线上，字面先按 dy 压到基线
f'translate({x + adv*sx/2} {baseline}) rotate({rot}) scale({sx} {sy}) '
f'translate({-adv/2} {dy - baseline})'
x += adv * sx + track                       # advance 跟着缩放走
```

### 6. 叠字：每次出现都重写一遍

「天天」「开开心心」里两个相同的字，**必须是两份不同的几何**。

换种子是不够的 —— 只换了线的抖法，骨架、重心、每一笔的长短完全一样，
两个字并排放一眼就看出是同一份图复制的。**手写的人不会写出两个一模一样的字，
但他也不会只是把同一个字抖歪一点 —— 他会写得不一样长、不一样重。**

**这件事现在是自动的**：`scripts/vary.py` 在骨架层重摇，每一次出现都是重新
写的一遍，所以同一个字可以出现无限次。默认不需要复制字形；如果需要一份
可控的备用画法，可以在编辑器里再次添加这个字，字库会用 `天2`、`天3` 这样的
内部名字保存，界面仍显示为「天」并标记 `v2`、`v3`。排版时这些变体会按出现次序
轮换，之后仍会继续重摇，避免每次都像复制素材。编辑器新增同字时会直接创建一份
空白变体；画布下方输入参考字后即可对照着重新描摹。输入法组字期间允许暂存拼音或多个字符，保存时只取第一个字符。

量过一次：手工另写的那份跟本体差最大 2.8 / 平均 1.9 个单位；自动重写差 4.4 / 2.4，
而**两次自动重写之间**差 5.7 / 3.8 —— 手工那份的两倍。手工的做法在每个维度上
都被盖过了，所以不是「自动的够用了」，是「手工那套本来就更弱」。

下面这张表是 `vary.py` 的幅度规格（也是手工微调时的尺子）：

| 维度 | 挪多少 | 例（同一个字的两种写法） |
|---|---|---|
| 笔画长短 | ±2–4 | 上横 `H43` → `H41`，下横 `H53` → `H54` |
| 横的高低 / 竖的起收 | ±1.5–3 | 下横 28 → 30 |
| 撇捺的斜度 | ±3–5（末端坐标） | 撇尾 `12 51` → `13 53`，捺尾 `53 52` → `52 51` |
| 重心 | 整体上下 ±2 | 第二遍比第一遍写低一点 |
| 折角半径 / 钩的挑度 | ±0.5 / ±2 | 「心」的卧钩尾巴挑到 34 而不是 36 |

**别改结构**：部件的相对位置、笔顺、笔画数一个都不能动 —— 改了就是另一个字，
不是同一个字的第二种写法。

**至少动两处，每处都要在显示尺寸上看得见**（64 网格上 2 个单位起步；
挪零点几个单位是自欺欺人，渲出来还是同一个字）。

### 结构不变量得验，不能靠「生成时小心」

位移一旦大到看得见，就一定会有几次把该分开的两笔挤到一起、或者把该连的拉开 ——
实测 96 次重写里坏了 34 次。「始」的台两笔缠成一个 6、「都」阝耳旁挨上左半，
都是这么来的。

所以 `vary.py` 先把关节找出来：两笔端点凑在一起的归成一个关节一起动；
一笔的端点落在另一笔中段上的（「天」的撇捺挂在下横上），记下参数位置，
宿主变形完再贴回去。然后**逐对笔画比对变形前后的最小间距** ——
连着的必须还连着、分开的不许挤到一起。不合格就换个盐重摇、幅度降一档，
全都不合格就退回原样：**这个字这次不变，比写坏一个字强得多。**

判据还是那一条 —— 摆一排看：像同一个人写了 n 遍 ✓，像同一张图 ✗，像 n 个人写的 ✗：

```bash
python3 scripts/handdraw.py vary my-font.json -n 6 -o vary.html
```

## 画一个新字

### 第零步：把这个字的印刷体先渲出来对着看

**一律简体。** 别写出繁体字形来 —— 最容易翻车的是那些「简化只差一笔」的部件：
`见`（框里**一**横）不是 `見`（框里两横 = 目）、`门`不是 `門`、`画`不是 `畫`。

**别凭记忆写骨架。** 「业」到底几横、「处」的卜从多高起笔、「膏」下面是月还是日 ——
凭印象写十有八九是错的，而写错了后面怎么调抖动都救不回来。

**每个字都要做这一步，包括「这么简单还用看？」的那些。**
实测翻车的六个字里，「业」（多写了一条中横）和「问」（门的横折钩画成从左竖起笔）
都是我觉得不用看的字。对着印刷体**数一遍横、数一遍竖**再动笔。

手上有字体文件就把目标字渲一张大图摆在旁边（`fontTools` + `SVGPathPen` 取轮廓，
不要拿它的轮廓当骨架，只当**结构参照**）：

```python
from fontTools.ttLib import TTFont
from fontTools.pens.svgPathPen import SVGPathPen
f = TTFont(path); gs = f.getGlyphSet(); cm = f.getBestCmap()
pen = SVGPathPen(gs); gs[cm[ord('业')]].draw(pen)   # 填充画出来，只用来看结构
```

画完把自己的骨架和印刷体**上下并排**渲一张对照图，一个字一个字比。
这一步能挡掉上面那张表里的绝大多数「读成另一个字」。

### 第一步：拆笔顺，一笔一条 path

按真实笔顺拆。一笔就是一条 `path`，不要把两笔连成一条，也不要把一笔拆成两条 ——
收笔越位是按「一笔」算的，拆错了两头都会多探出一截。

### 第二步：先摆结构，再调细节

左右结构先定分界线（`情` 是 忄 占 8–22、青 占 25–56），
上下结构先定横向分界（`今` 的人字头到 y=34，下面归 丶 和 乛）。
结构错了怎么调笔画都不对。

### 第三步：三个尺寸上验，然后问一句

> **它会不会被读成另一个字？**

这是汉字特有的失败模式，比「糊掉」更常见。实测踩到的：

| 想写 | 读成了 | 为什么 | 怎么修 |
|---|---|---|---|
| 见 | 兒 | 框太高、腿太短，框内两道横看着像「臼」 | 框压到 15 高，腿放长到 30 |
| 天 | 夭 | 撇捺完全对称，像个「人」压在两横下 | 捺从撇的**上段**起笔，比撇长、比撇平 |
| 天 | 夫 | 撇从顶横**上头**起笔（y=8，顶横在 15），顶上多出一截出头 | 撇的起笔**落在顶横上**（y=15），往下穿过第二横再撇出去；出头的是「夫」 |
| 切 | 刃 | 刀的竖跟撇拉成两条平行竖 | 竖收短，撇加斜度往左下甩 |
| 处 | 永 | 卜的竖起笔太低，撇和捺在正中间交出一个 X | 竖拉到 y=17 起笔贯到底，撇尾甩到左下 14，捺压平 |
| 是 | 昊 | 下半的撇捺从同一点分叉，成了「大」 | 撇捺都挂到竖的**底端**（y=49），中间那横往上提到 38 |
| 牙 | 才 | 长撇从中间那道长横起笔，穿不过去 | 撇改成从**顶横**起笔，斜穿过长横再落到左下 |
| 业 | ⺌一 | 两竖等长等距、外面两点也画成竖，成了一把梳子 | 两点写成带斜度的短曲线 |
| 业 | 业多一横 | 凭印象加了一条中横 —— **业只有底下那一条横**，两竖直接落到它上面 | 删掉中横，两竖拉长到底横 |
| 处 | 永 | 捺画成一条直的对角线，和撇在正中间交出个 X | 捺是**平捺**：下去之后要在底部铺平往右走，尾巴甩出字外 |
| 问 | 冂 + 点 | 门的横折钩从左竖起笔，围成一个封闭的框 | 横折钩**从中间偏右起笔**，和左竖之间留出明显的空 |
| 剧 | 看着缺一笔 | 古的竖夹在横和口之间只剩 5 个单位，渲出来看不见，古读成「一 + 口」 | 竖在横上头**露出 6–8 个单位**，下头接到口的顶边 |
| 砚 | 硯（繁体） | 见的框画得又矮又宽，里头一横把它切成两格 = 目 | 框要**竖长横窄**（高 22 宽 17），腿比框短 |
| 如 | 女 + 小方块 | 口画成右上角一个小方块 | 如的口是**高**的，占整个字高（20→52） |
| 乐 | 爻 / 两个 X | 顶上「横+竖钩」画成两条分开的斜线，跟下面撇捺交叉出双十字 | 顶部是 **撇 + 横**（不是一笔竖折 —— 这里最容易写错）：撇从顶横左端起笔往左下走，横往右拉、右端小下折；竖钩单独从横下面往下，撇捺落在竖钩两侧 |
| 足（路字旁） | 缺一笔，像根光杆 | 第一版改成「口 + 一条竖 + 一条底横」，看着更干净了，但漏了**中间那道横**（形似「正」字下半），渲出来一眼就知道缺笔画 | 足字旁 = 小口 + 竖 + **中间一道横** + 底部一道微斜的横（提），四笔一个不能少；改完**必须**跟印刷体重新核一遍笔画数，「看着顺眼」不等于「笔画够」 |
| 那（哪字右半） | 牙 | 右半的脚画成一条长撇甩出框外，跟阝耳旁的钩混在一起读成「牙」 | 左半只用**横折 + 短竖**收在框内，不另加甩出去的撇；阝耳旁的钩和竖跟左半留出 3–4 个单位的间距，别挨着 |
| 始（女字旁） | 撇点和撇交叠成疙瘩 | 女的撇点画在左上，跟长撇的起笔点太近，两笔在顶部拧成一团 | 撇点在**右上**（不是左上），长撇从撇点左边另起笔，两笔起点错开 6–8 个单位 |
| 台（始字右半） | 两笔缠成一个「6」 | 撇和横折的收笔点几乎落在同一坐标，两条本该分开的短笔挤成一个闭合圈 | 两笔的**终点也要错开** 3–5 个单位，不能只错开起点；短笔挤在一起比长笔挤在一起更容易糊，因为可调整的空间更小 |
| 乍（作字右半） | 丰 / 王 | 竖钩探到了顶横**上头**（比如从 y=12 起笔而顶横在 y=21），顶部多出一截像另一笔 | 竖钩起笔的 y 坐标要**卡在顶横那条线上**，不能比横还高 —— 这是「乐」那条「顶部别探出去」规矩的另一次踩坑，同一类错误认出来会更快 |
| 乐 | 朱 / 矢 | **两处一起错才会读成朱**：① 顶上那一撇画成了「盖在横上面的一小勾」，起笔探到顶横**上头**，看着就是「矢」的那一撇；② 竖钩只走到 y≈46 就收，钩甩 3–4 个单位，小尺寸上等于没有 | 撇的起笔**就落在顶横的左端**（同一个点，y 相同），一路撇到长横**以下**（19,14 → 9,32）；竖钩从顶横下面 5 个单位起笔、**贯到 y≈51**，钩甩到 x≈22；下面的撇捺**不接竖钩**（竖在 32，撇起 26、捺起 38），各自甩到 8 / 56。改完的轮廓是「厂 + 一 + 亅 + 八」，朱是竖从顶贯到底 |
| 的（勺） | 日 + 一撇 | 把「勺」当成一条弧线一笔画完，外框既不成框、点也没了 | 勺是**三笔**：撇（从右上斜下来）、横折钩（横 → 竖 → 钩往左上挑）、点（框里那一小竖点）。一笔画完的弧线永远读不出「勺」 |
| 心 / 想 | 一个碗吞了三个点 | 卧钩画得又深又圆（像半个圆），三个点掉进碗里连成一片 | 卧钩要**铺平**：起笔 y≈41，底 y≈52，宽度拉到 20 个单位；尾巴挑到 y≈44（抬 8）。三个点各留 3–4 个单位的空，中点别落在钩的正上方 |
| 女（始字旁） | 从 / 父 | 撇点的第二段（点）拉得跟长撇一样长，两条对角线交成一个大 X | 点那一段只走到 y≈40 就收，比长撇短 6–8 个单位；横压在 y≈32，从 x=7 拉到 30，用横把 X 压住 |
| 讠 | 3 / 乙 | 横折提的竖段画成了弧（`C` 带出个肚子），跟上面的横折连起来像个「3」 | 竖段用**直线**（`L`）从折角落到 y≈44 再挑，别用 `C`；横从 x=7 起笔拉到 17，折角半径 2.5 |

### 两道平行的横之间至少留 6 个单位

线宽 2.8，两道横差 4 个单位的话白缝只剩 1.2 —— 在 44px 上等于 0.8px，
渲出来还是一道粗横（留够 6 个单位才有 3.2 的白缝，也就是 2.2px）。**这一条在「日」「旦」「寸」堆叠的字里最容易踩**：

| 字 | 第一版 | 问题 | 改成 |
|---|---|---|---|
| 是 | 日底横 30 / 长横 34 | 差 4，糊成一道，「日 + 一」读不出来 | 日压到 12–28，长横下到 35（差 7）|
| 是 | 长横 36 / 疋横 39 | 差 3，下半整个粘死 | 长横 35 / 疋横 42（差 7）|
| 得 | 日底横 30 / 旦一 34 / 寸横 40 | 差 4 和 6，上面那对会粘 | 29 / 35 / 41，三道之间都留 6 |

**别只看 y 坐标差，要看两笔在 x 上重不重叠。**「时」的寸横（y=27，x 36–59）
和日中横（y=32，x 10–32）差 5，但一左一右不重叠，没有问题 —— 按坐标差
一刀切会把这种误报出来。

用逐对笔画的真实最小间距查（`vary.gaps`，编辑器和 `vary` 命令都在用）：

```python
import vary, dpath
st = [dpath.parse(e['d']) for e in items['是']]
[(i, j, g) for (i, j), g in vary.gaps(st).items() if 0.4 < g < 4.0]
```

落在 **0.4–4.0** 之间的笔画对要挨个看：要么本来就该相接（日的横折跟底横收口、
撇跟竖交汇，间距 0.5–1.5 是对的），要么就是会粘的，得拉开。

**跟另一个字骨架撞了（乐/朱、天/夭），别指望靠一个钩的细节分家。**
把两个字的印刷体**并排渲一张**，先找整体轮廓的差别（乐的竖只占中下段、朱的竖贯到顶），
照着轮廓改骨架；只把钩加长 2 个单位，在 44px 上还是同一个字。

**「渲出来觉得眼熟」是最危险的信号**：乐、足字旁、乍都出现过「改完感觉像那么回事，
实际缺一笔或多一截」——**每改完一个字，回去用第零步的印刷体大图，一笔一笔点着数**，
不要凭直觉判断「够不够」。

**这类问题不能靠调滤镜救，只能改骨架。**

### 部件复用：讠 / 阝 这类偏旁存一份，跨字直接用

「认」「识」的讠字旁、「那」「哪」的阝耳旁，都是**同一个偏旁在不同字里出现**，
不是叠字（叠字规矩见上面「换写法不是换种子」）——直接**复用同一份坐标**，
挪到新字的左 / 右边界上即可，不用像叠字那样另写一遍。

```
讠（左偏旁，窄，x 7–20）：
  点   M13 13 L10 18
  横折提 M9 25 H16 Q19 25.5 17 29 C15 33 17 36 23 40
```

### 第零步的省事做法：编辑器的印刷体底图

```bash
python3 scripts/handdraw.py edit my-font.json
```

印刷体直接垫在 64 网格画布底下（默认黑体，也可切换宋体、楷体），画布下方的单字
输入框即可更换当前参考底图，对着描就行；输入法组字期间允许暂存拼音或多个字符，保存时只取第一个字符。每一笔的起收点从网格刻度上直接读。
左栏加号先创建未命名的空白字形，输入参考字并保存后才写入字形标题。**这不代替「数一遍横、数一遍竖」** ——
底图只保证你不写错结构，写不写得成字还是靠上面那张「读成了」表。

要一次看一整批新字（比对着挑哪些先画）还是用下面这个法子。

### 批量渲印刷体対照

手上没有目标字体文件时，直接拿系统黑体渲一张网格图，比 fontTools 取轮廓更快，
足够当「结构参照」：

```python
from PIL import Image, ImageDraw, ImageFont
font = ImageFont.truetype("/System/Library/Fonts/STHeiti Medium.ttc", 160)  # 简体
# 逐字画进一张网格图，渲完整批一起看，比一个一个查字典快
```

一次渲完这一批要写的所有新字，摆成网格，画骨架时开着这张图逐个字对照——
比凭记忆画完再挨个纠错省一半时间。

**再往前走一步：把 64 网格的刻度画在印刷体上。** 一格 = 一个字，按 `u*(cell/64)`
每 4 或 8 个单位画一条线并标上数字，字按 `anchor="mm"` 居中渲进去（字号取
cell 的 0.78 左右，正好落在 7–57 的字面里）。这样每一笔的起收点都能**直接读出
坐标**再抄进 `d`，不用先画一版再回头调——一批 20 个字，读坐标画完的第一版
就有八成能直接用，凭感觉画的第一版一半要返工。

难认的字（笔画交叠的 路 我 那 始）单独再渲一张 640px 的，刻度加密到每 4 个单位。

### 一行字太长时，提前按显示宽度拆行

`title_svg` 一行是 `len(text) * 64` 宽，8 个字在手机屏（约 340px 内容宽）上
显示到 44px 高时已经接近撑满。**超过 8–9 个字就别硬塞一行**——
按语义断句拆成两行（两个独立的 `title_svg` 调用，各自存一张图），
而不是缩小整行的高度去迁就宽度：缩过头会跌破 30px 糊字的门槛。

判据：目标显示高度 × 字数 是否会超过容器宽度？会 → 现在就拆行，
不要等渲出来发现字被压扁了再回头改。

### 44px 是**整张图的显示高度**，别为了塞下一行就往下压

一行 9 个字压到 38px 是这支笔最常见的翻车方式：单看字库里每个字都对，
排进页面就是「大部分看不出字来」。拆完行还是放不下，就让整段**等比缩**，
不要压高度：

```css
/* 外层按最宽那行的 44px 宽度卡上限，窄屏才等比缩 */
.lines { display: flex; flex-direction: column; gap: 7px; }   /* width: min(100%, 最宽行 * 44 / 74) */
.lines img { display: block; width: 100%; height: auto; }      /* 各行按原生宽占百分比 */
```

关键是**两行绑在一起缩**：各行单独写 `max-width` 会让长的那行先被卡住，
出来一行大一行小，一眼看出是两张图拼的。

### 拉丁词 + 汉字混一行，两张图比一张混排划算

一行里「hey～路过的伯乐」这种拉丁词 + 汉字混排，**不要**扩展 `title_svg`
去支持变宽字符——拉丁按 `lines_svg`（每个字母各带 `adv`）单独出一张图，
汉字部分照常走 `title_svg`，两张 `<img>` 用 `flex; align-items: flex-end`
拼在一行，靠 CSS 的 `gap` 留字距。

两张图各自的显示高度要按**原生高度比例**换算，不能给一样的像素高度——
拉丁的 `lines_svg` 原生高度（约 66，含上下伸部）比汉字 `title_svg` 的原生高度
（64 格 + padding ≈ 74）矮一截，直接给相同高度会让拉丁词看着偏大。
按同一个缩放系数 `k` 分别算：`汉字高度 = 74k`，`拉丁高度 = 66k`。

### 中文一行、英文一行上下排：各缩各的，线宽要补

中文一句、英文译文一句上下叠放（标题 + 副标题、README 展示图）时，两行**各自**按
目标宽度缩放，让两行的**字面宽度**差不多（英文可以比中文宽 2–5%，拉丁字面矮，
等宽时看着反而窄）。字距、词距仍然用默认值，不要为了凑宽度去动字距。

两行缩放倍率不一样，**同一个 `sw` 落到画布上就不一样粗**：英文一行字母多，
倍率往往只有中文的 2/3，笔画细一圈，看着像两支笔。按画布上的实际线宽反推英文的 `sw`：

```
sw_英文 = sw_中文 × 中文逐笔 w 的平均值 × k_中文 / k_英文
```

线宽不参与排版，换 `sw` 重出一遍不会改字距和 viewBox。

竖向按**字面框**居中，不按 viewBox：两行字面框加上行间距当作一块，
上下留白量出来相等（1200×400 的画布上，行间距 40 左右、上下各留约 90）。

### 把行预览嵌进别的 SVG：外层的 `stroke-width` 要带上

`render_row` / `renderRow` 出来的 `<svg>` 把基础线宽写在**外层**，只有带了提按 `w`
的笔画才在自己的 `<path>` 上写 `stroke-width`。拼图时如果只取里面的 `<g>` 扔掉外壳，
汉字（每笔都带 `w`）看着没事，**拉丁字母（没有 `w`）会掉回 SVG 默认的 1**，
细成发丝。剥外壳时把外层的 `stroke-width` 挪到这一行的 `<g>` 上。

### 做展示图时：书写动画和种子

- **逐笔书写动画**：用 `stroke-dasharray` + `stroke-dashoffset`，排程照编辑器「展示」的
  （一笔按弧长定时长，笔间、字间各停一拍）。没起笔时，实线段要退到**起点之前再往后几个单位**
  （偏移量 = 虚线长 + 6），正好停在起点上的话，`round` 线帽会在起笔处留一个墨点。
- **展示「同一骨架、不同写法」**：默认参数下单字的变化不大，随手挑的三个种子常常看不出区别。
  按落进格子后每笔采样点的平均位移，在一批种子里挑**两两差异最大**的一组，大小、倾斜、笔长才分得开。

### 同一个部件，在不同字里比例完全不同

`口` 在「如」里是**高**的（占整字高的 2/3），在「问」里是**小**的（缩在框中间偏上），
在「古」里是**扁**的。照搬上一个字里的那份几何，字就走形了 ——
**每个字的部件都要按这个字重新量一遍。**

反过来也有陷阱：修「见」时我试过删掉底横，结果整个字变成了「月」。
**删笔画之前先渲染一次** —— 汉字的每一笔通常都在承担辨识功能。

## 拉丁小写

同一支笔也能写英文标语。规矩和汉字一样（画骨架、`amp` 0.65、转折自带半径），
但有三处不同：

| | 汉字 | 拉丁小写 |
|---|---|---|
| 格子 | 一字一格 64，**等宽** | **每个字母各带各的 `adv`**（i/l 14、t/f 20–23、a/e/o/n 28–31） |
| 竖向 | 字面 7–57 撑满格子 | 上伸部 10 / x 高顶 24 / **基线 48** / 下伸 56 |
| 字距 | 无（格子自带） | **每个字母后面再加 7**（约字母宽的 1/4） |
| 词距 | 无 | **26**（另外还会加一个字距） |
| 行距 | 一行为主，很少排两行 | **60**（约 2.5 倍 x 高） |

### 字距是这支笔的一半

第一版我把字母按 `adv` 紧挨着排，出来是「印刷体抖了一下」。手写标语的气口
**全靠字距撑**：字母之间留出小半个字母的空，整行才松得下来，也才压得住
旁边那几行正文。字距不够 = 整段看着比实际重一档。

**字距、词距、行距三个一起调**，动一个另外两个都要跟：
字距松了行距不跟着松，两行会黏成一块；词距不跟着松，词和词就分不开。
实测这一组配比是 `7 / 26 / 60`。

配套的还有**整体放小**：字距一松，同样的信息量占的宽度多了近三成，
显示高度要跟着往下调（实测两行标语 56px 高就够，62px 已经压过正文了）。

四条参考线定死了整段的节奏 —— **每个字母都要老老实实落在这四条线上**，
浮一个就像掉了一颗牙。圆头字母（o/e/a/s）上下各**超出 0.4–0.8**，
不然并排看会比 n/i 矮一截，这是所有字体都要做的视觉补偿，手写也一样。

### `adv` 按字面量，左右边距一样

字距 7 是加在 `adv` **后面**的，所以 `adv` 里自带的左右边距必须小而且一致：
字面左边留 **2.5**，右边留 **2.5**，`adv = 字面宽 + 5`。画字母时顺手在格子里
「居中」画、`adv` 凭感觉写 30，出来的边距一个 8 一个 4，再叠上字距 7，
整行松得散架，而且字母之间一宽一窄（实测「Handm ade」「d」「e」撞在一起就是这样来的）。

别凭眼睛调：画完按骨架坐标算出每个字母的字面左右边，平移到左边距 2.5，
`adv` 写成字面宽 + 5。上面表里的 `adv` 参考值（a/e/o/n 28–31）就是这么量出来的量级。
标点（, .）一样，别给它留一整个字母的宽。

### 大小照样逐字母摇，但**缩放绕基线做**

汉字那套逐字大小（±9%、相邻至少差 3.5%、再压扁抻长一点）拉丁全部照搬，
只有支点不一样：**汉字绕字面中心，拉丁绕基线**。绕中心缩会让小一号的字母
整个浮起来，一行字的下沿变成波浪。

配套要做的是**排版时按字面把每个字母压到基线上**，别信几何里的原始坐标：
另写的那一遍为了「写得不一样」常常矮一点（实测另写的 o/e/s 底边落在
44.4–46.8 之间，比 n 的 48 高了 1–3 个单位），单看字库没问题，排成一行就是
中间几个字母浮空。压线的算法只有一行：`dy = 48 + 圆头补偿 - 字面底边`。
带下伸部的（y / , /.）不参与，它们本来就该掉到基线以下。

**骨架层重摇之后这条更要紧了** —— 自由端能动 ±3，一个 `n` 的竖脚很容易掉到
基线以下或者浮起来。所以压线**必须按重摇后的那份几何算**，不是字库里那份
（`row.py` 的 `polys_of(name, i)` 就是为这个带上出现序号的；汉字那边的摆正
同理，实测拿错几何会让最坏的字在 44px 上偏 4.6px，是逐字位移设计值的 6 倍）。

字母被摇大摇小之后，**advance 也要跟着乘同一个系数**，不然大字母挨得紧、
小字母之间空出一块。

### 尺寸下限比汉字低

拉丁一个字母 1–3 笔，**28px 还认得出**（汉字要 44px）。所以标语可以排得比
中文标题小一档。

### 重复字母跟叠字一样：每次出现都重写

「narrative first, / tools after.」里 `t` 出现 **4 次**、`r` 4 次、`a` 3 次。
别把 `t / t2 / t3 / t4` 各手工写一遍存进字库 —— 跟叠字走同一条路就行：
`vary.py` 每次出现重摇一遍，字库里一个字母只存一份。

**幅度是这里唯一容易做错的地方：至少动两处，每处 2–4 个单位。**
按「拉丁量级减半、±0.4–1」去挪试过，一眼就被看出「这个 s 又复用了」——
半个单位在 60px 的显示尺寸上不到 0.5px，等于没改。`vary.py` 的幅度就是照
这一条定的。

手工微调一个字母时，能动的地方和汉字不一样，按这几样挑两样动：

| 动什么 | 例 |
|---|---|
| 碗的胖瘦 / 整体宽度（`adv` 跟着改） | `a` 30 宽 → 另一遍 27 宽 |
| 收笔挑不挑钩 | `t` 带钩 → 另一遍平收；`i` 的竖尾巴带钩 |
| 横的长短和高低 | 横 16 长且靠上 → 12 长且靠下 |
| 肩 / 臂的角度和伸出量 | 挑高伸远 → 压平收短 |
| 上伸部高度 | 到 12 → 到 15 |
| 起笔留不留口 | 闭合 → 左上留个小口 |

判据和汉字一样：两份并排放大看 —— **看得出是写了两遍 ✓，看不出差别 ✗。**

拉丁字母也画在同一份扁平字库里；需要字宽时，在字母的第一笔带 `adv`。
新字母往字库**末尾**加。

## 字库

**这套工具不自带字体。** `assets/glyphs.json` 是一份空的扁平字库模板，汉字和拉丁字母
都直接放在 `items` 下；一个字至少存一份，需要可控的备用画法时可追加 `字2`、`字3` 等变体。

每次要写一句话，就把这句话用到的字画进一份自己的 JSON
（`edit my-font.json`，文件不存在会自己建）。画到第几个字都能随时排一行看效果 ——
字库是攒出来的，不是先备齐再用的。

**字库存的是结构，不是成品。** 一个字存一份正确的骨架就够了 ——
笔顺、笔画数、部件的相对位置，这些是「读成了」表挡住的东西，必须固定；
每一笔具体多长、横多高、撇多斜，那是每次写的时候摇出来的。

新字往**末尾**加（种子按顺序算，插中间会让后面所有字重抖）。

改字用编辑器最省事：`python3 scripts/handdraw.py edit my-font.json` ——
拖的是骨架，存盘写回这份 JSON，没动过的笔画一个字符都不变。看效果：

```bash
python3 scripts/handdraw.py gallery my-font.json -o g.html
```
