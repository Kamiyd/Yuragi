# 滤镜参数表

只有想改**整体手感**时才读这一份。想改一个字的形，改它的几何。

## 滤镜在做什么

`scripts/hand.py` 只做三件事，加起来一百来行：

1. **沿法线叠低频噪声** —— 三阶正弦（1.3 / 2.7 / 4.1 个周期），手画的线不直
2. **收笔越位** —— 开放笔画两头各探出去一点，笔收不住
3. **转角收紧切线** —— 折线按弧长重采样成平滑贝塞尔，转角处把点重复一次，
   不然所有折角都会被磨成一坨

外加三道**不许自交**的闸（见下）—— 只保证路径不打结，不改手感。

## 参数（在 `scripts/handdraw.py` 顶部）

| 参数 | 值 | 为什么是这个数 |
|---|---|---|
| `AMP_SHORT` | 0.14 | 弧长 < 5：点、短撇这种三五个单位长的笔画，按长笔画的幅度抖会直接散掉 |
| `AMP_MID` | 0.24 | 弧长 5–11 |
| `AMP_LONG` | 0.34 | 弧长 > 11 |
| `CORNER_DEG` | 32 | 转向超过它就算硬角，滤镜在那儿把幅度压到 **0.25 倍** |
| `OVER_SHORT` / `OVER_LONG` | 0.28 / 0.5 | 收笔越位。闭合笔画不越位 |
| `STEP` | 1.35 | 重采样步长 —— 直接决定曲线段数，也就是**体积** |
| `SIMPLIFY` | 0.45 | 进滤镜前抽稀：一个半径 2.5 的小圆本来会摊成 40 个点，抖完就是 40 段曲线 |
| `PREC` | 2 | 坐标小数位。**不能是 1** —— 收笔越位那截只有 0.45 长，0.1 的量化会把它的切线拧歪，折出半径 0.1 的假弯，见「不许自交」 |

这张表按 24 网格标定。汉字走 64 网格，所有参数按 `vb / 24` 等比放大，不用手动改。

**这些数不是拍的，是在 15px 上逐档看出来的** —— 那是这支笔的通用标定，
标的是「小到什么程度还立得住」。汉字比图形不经抖，所以在它之上还压了一道
逐笔的 `amp` 0.65（见下）。两层是乘起来的。

## 这里没有的两个数

`amp` 和 `w` 是**逐笔**的字段，写在几何里，不是滤镜参数：

| | 在哪 | 干什么 |
|---|---|---|
| `"amp"` | 元素上 | 这一笔的抖动倍率。汉字一律 **0.65** —— 「口」抖散了就不是字了 |
| `"w"` | 元素上 | 这一笔的线重倍率，0.85–1.15，用来做提按，见 `glyphs.md` |

调一个字的手感先动它自己的 `amp`，不要动这张表 —— 表里的数一动，整套字全变。

## 骨架层的幅度（`scripts/vary.py`）

上面那张表是**线条**的抖动，同一份骨架抖出不同笔迹。骨架层换的是**写法** ——
每一笔多长、横多高、撇多斜，每次重摇。规格来自 `glyphs.md` 的叠字表：

| 参数 | 值（64 网格） | 是什么 |
|---|---|---|
| `JOINT` | 1.8 | 关节位移 —— 连着的笔画一起动，结构的松紧 |
| `FREE_T` / `FREE_N` | 3.0 / 1.5 | 自由端沿切线 / 法线：笔画长短、撇捺斜度 |
| `CURVE` | 1.2 | 控制点沿法线：弯度、钩的挑度 |
| `BODY` | 2.0 | 整字重心 |
| `EPS` | 2.0 | 判定两笔「连在一起」的距离 |

**幅度往下调没有意义**：64 网格上 2 个单位是肉眼门槛，低于它等于没重写。
往上调会让守卫的重试率飙升（结构一直摇坏），字反而更少变化。

## 要动就动幅度那三档

`CORNER_DEG` 和 `STEP` 一动，整套字全变 —— 而且 `STEP` 还会连带改体积。
想让整体更野一点，把三档各 +0.05；想更收敛，各 −0.05。别的别碰。

## 字库级手感：不用改代码的那四个

上面那张表是**写死在 `handdraw.py` 里的通用标定**，一改所有字库跟着变。
想只让**这一套字**更毛一点、越位少一点，改几何 JSON 的**字库级字段** ——
它们是倍率，默认 1.0，乘在上面那张表之上：

| 字段 | 乘在哪 | 拖大了会怎样 |
|---|---|---|
| `amp` | 每一笔的抖动幅度（跟逐笔 `amp` 相乘） | 线更毛。汉字过 1.3 开始有笔画糊在一起 |
| `over` | 收笔越位 `OVER_SHORT/LONG` | 笔画两头探得更远，更「写」；过 1.8 折角会支出小刺 |
| `jit` | 排一行的大小起伏（`row.han_layout` 的 `amp_k`，逐字缩放/压扁/旋转/位移一起缩放） | 0 = 一版字帖；过 1.5 像排错了 |
| `vary` | 骨架层重写幅度（`vary.vary` 的 `amp`） | 同一个字每次写得更不一样；过 1.5 守卫退回原样的次数会飙升 |

加上 `sw`（线宽，**绝对值不是倍率**），这五个就是编辑器右栏「整套字的手感」
那五根滑杆。**拖它们 = 改这套字本身**，存盘写进 JSON，`write` 出图读的是同一份。

```json
{"vb": 64, "sw": 2.8, "amp": 1.2, "over": 0.8, "items": {...}}
```

代码里这四个字段缺省仍然是 1.0 —— 老的几何 JSON 一个字段都不用加，行为完全不变。
**但新建的空字库不再落在 1.0 上**，见下。

## 新建空字库的预设

`edit my-font.json` 建出来的空库（也就是 `assets/glyphs.json`）带这一组数：

| | `sw` | `amp` | `over` | `jit` | `vary` |
|---|---|---|---|---|---|
| 单一字库 | **2.8** | 0.9 | 1.0（不写） | 0.9 | 0.9 |

这几个数是从真实字库里收出来的：

- **`jit` / `vary` 0.9** —— `row.py` 在 `amp_k=1.0` 上的那组数
  （`0.09 / 0.035 / 0.035 / 1.5°`）可作为通用起点；具体字库可按
  排版效果微调。

**这只是开局值，不是规格。** 攒到十几个字之后照着自己这套字重调一遍
（编辑器右栏那五根滑杆），存盘就写进 JSON 了。

## 不许自交

浏览器是**解析式描边**，直接按曲线算覆盖率，路径怎么打结它都画得对。
但另一类渲染器（Figma、部分 SVG→PDF）是**先把描边摊成轮廓再填充** ——
中心线向两侧各偏移半个线宽。只要中心线在哪儿的**曲率半径小于半线宽**（`sw 2.8`
→ 1.4），内侧那条偏移线就会翻转自交，那一块被 nonzero 绕数抵消成 0，挖出白楔子。

现象是：**预览好好的，导出丢进 Figma 就缺角、笔尖少一块。** 同一份 `d`，两个渲染器。

滤镜这边有三道闸，都是「不改手感、只保证不打结」：

1. **退化段不画**（`hand.py` `_cr`）—— 转角处重复的那个点会让 Catmull-Rom 生成一段
   首尾同点的三次曲线，两个控制点一个冲过转角、一个反向折回，画出来是个直径
   零点几的**小圈**。跳过这一段，相邻两段的切线计算完全不变，折角该多尖还多尖。
2. **手柄不越过对端**（`hand.py` `_cr`）—— 两个控制点在弦上的投影之和不超过 1，
   超了等比收回来。收笔越位那一小截旁边跟着一整步长的段，切线是按邻点间距算的，
   不收就会在笔尖打圈。控制多边形一单调，这一段就不可能折回去。
3. **`PREC = 2`** —— 1 位小数在 64 网格上最大能把曲线推偏 0.07 个单位，凭空折出
   半径 0.1 的假弯。实测 6 套字库 511 条描边路径，中段曲率半径小于半线宽的
   从 492 条降到 203 条。2 位等于 `hand.py` 的原始输出，不再引入量化噪声。

剩下那 203 条是**骨架自己设计的硬折角**（横折、竖弯钩），曲率半径本来就趋近 0，
这三道闸管不着。要让 Figma 也干净只能把那几处夹角放缓 —— 那是字形设计的选择。

## 体积

抖动会把一条直线变成几十段贝塞尔，路径数据很贵。`STEP=1.35` 和 `SIMPLIFY=0.45`
缺一不可 —— 实测一套 40 枚的几何，缺任何一件就从十几 KB 涨到六十 KB。
汉字笔画比图形密，只会更贵。`PREC` 从 1 提到 2 会让 `d` 大**约 22%**，
这是换不打结付的钱，别再降回去。

改这两个数会同时改变手感和体积。动之前先跑 `gallery` 看小尺寸下还立不立得住。

## 确定性

同一份几何 + 同一个顺序 = 同一条路径。种子按字在字库里的**顺序**算：

```python
seed = idx * 7 + k * 3 + 1     # idx 是字的序号，k 是它第几笔
```

所以**新字往字库的末尾加**。插在中间会让后面所有字重抖一遍 —— 形状不变，抖法变，
diff 会很吵。**改一个字里的笔顺同理**，它会让那个字整个重抖（这是预期行为，不是坏了）。

编辑器（`handdraw.py edit`）实时预览走的就是这份确定性：它把骨架发回 Python
渲染，而不是在 JS 里另写一份滤镜。**别为了少一趟往返去移植 `hand.py`** ——
两份实现必然漂移，预览一旦跟 `handdraw.py` 出的不是同一条线，编辑器就在骗你。
