**把一句中文画成手写感的 SVG 字 —— 整条流水线跑在浏览器里。**

> 「写『示例文字』」→ 一行手写汉字，每次跑都是新写的一遍

**揺らぎ**（yuragi）＝ 晃动、起伏、涨落。名字就是这套东西的全部秘密：
骨架是直的，手感是**滤**出来的那一层晃动。

标志是**甲骨文的「永」**。

《说文》：「永，长也，**象水巠理之长**」—— 本义是**水流长**，甲骨文里就是一条长长的
主流带着支流，后来才引申出「永远」。水流、绵长、起伏，对得上 Yuragi。

骨架照《甲骨文編》450.4 收的第 1 式描的：右侧一条长 S 的水道、左上一条斜支流、
左下一个折回来的分支。那一条收了 **18 个「永」字形，写法各不相同** ——
三千年前这个字就没有一个固定的样子，这跟本项目「每次写都是新写的一遍」是同一件事。

还有一层：楷书里「永」是**永字八法**那个字 —— 八种基本笔画（侧、勒、弩、趯、策、掠、
啄、磔）就是拿它教的。对一个**画骨架、一笔一条 path** 的工具，这是整个汉字里最本分的
一个字。`yuragi-mark-kai.svg` 是它的楷书写法，同一个字的另一端。

两个都不是描出来的，是拿这个项目自己的流水线跑出来的，源几何在 `brand/`。

渲染、重写、排版原来全在 Python 那一侧，编辑器只是个前端；现在那几个文件被
逐行移植成 TypeScript，跑在浏览器里。没有后端、没有上传、没有 API key ——
打开网页就能画、能排、能导出。

## 它跟字体不一样在哪

字体的字是**写得对**的产物；手写的字是**画得不准**的产物。这套东西做的是后者，分两层：

- **骨架层**（`vary.ts`）—— 每一笔多长、横多高、撇多斜，每次写重摇一遍。
  所以「重复字形」三个字不一样，不用在字库里存第三种写法。
- **线条层**（`hand.ts`）—— 沿法线叠低频正弦、收笔越位、转角收紧切线。
  确定性的：同一份骨架 + 同一个种子 = 同一条路径。

**手感不是画出来的，是过滤出来的。** 骨架按规规矩矩的样子画（横是平的、竖是直的、
折角是尖的），手感由滤镜统一加 —— 这样加进来的每个字都是同一只手。

## 移植：怎么保证跟 Python 是同一条线

原来的规矩是「渲染只有 Python 一份实现，所以预览不可能跟出图不一样」。
搬进浏览器之后这条规矩没变，只是实现换了地方 —— 而**换地方最容易漂的不是几何，是数值语义**：

| 坑 | 处理 |
|---|---|
| `h * 16777619` 超过 2^53 就不是 32 位乘法了 | 全程 `Math.imul` + `>>> 0`（`src/lib/core/rng.ts`） |
| Python 的 `round()` / `%.2f` 是银行家舍入，JS 的 `toFixed()` 不是 | 自己实现精确十进制舍入（`num.ts` 的 `fmtFixed`） |
| `"%g"` 六位有效数字，JS 没有等价物 | `pyG()` |
| Python 的 `%` 跟除数同号 | `pmod()` |
| V8 的 `Math.hypot` 最后一位跟 CPython 不一样 | 补偿算法实现正确舍入的 `hypot()` |
| Python dict 保序，JS 对象把纯数字键排到前面 | 编辑器把顺序单独保存在 `editor.glyphOrder`，纯数字字形名也能保持添加顺序 |

判据不是「看着差不多」，是**逐条字符串相等**：

```bash
npm run parity:fixtures   # 用 reference-python/ 那份原实现生成标准结果
npm run parity            # TypeScript 重算一遍，逐条比对
```

现在是 **4299 项全部一致**：d 串、整行 SVG、transform、逐字大小表、存盘文本，
全是精确比对；折线坐标和间距表按 1e-12 比。
`reference-python/` 保留原始 Python 就是为了这个 —— 它不参与网页运行，是**对照的标尺**。

## 目录

```

  num.ts             Python 的数值语义：舍入、格式化、hypot
  rng.ts             确定性随机（FNV + 雪崩混合）
  dpath.ts           d 串 <-> 可编辑节点表
  flatten.ts         SVG 图元 -> 折线
  hand.ts            抖动滤镜 —— 这支笔本身
  vary.ts            骨架层重写：同一个字每次写出来都不一样（保结构）
  row.ts             排一行字：摆正 / 逐字大小 / 相邻差值 / 包围盒
  draw.ts            几何 -> 手绘路径 -> SVG（handdraw.py）
  library.ts         字库读写、编辑器表示、存盘格式（edit.py）
  render.ts          单字渲染 + 整行渲染（原来的 /api/render、/api/row）
src/lib/api.ts       原来那层 fetch 的位置：接口形状不变，请求不再出门

tools/parity/        跟 Python 的逐条对照
reference-python/    原始 Python 实现，只用来生成标准结果
```

## 一份工程，不是一个字库管理器

界面上只有**一份工作文档** —— 你正在写的这一行。浏览器里留一个槽位是为了防手滑关标签页，
不是存档系统：没有字库列表、没有切换、没有云端。

要带走、要回来，走**导出分组底下那两个按钮**：「下载工程文件」「打开工程文件」。
一份 JSON = 这一版的骨架 + 手感 + 种子，**它仍然是唯一的真相层**。

> 为什么不像别的小工具那样导出完就清空？因为那些工具的输入是七根滑杆，
> 丢了重拨二十秒；这里的输入是你一笔一笔描出来的骨架，一个「情」11 笔，
> 一句八个字小半小时。**参数可以不存，创作的内容不能不存。**
> 而且种子的全部意义是「钉住某一版」—— 骨架没了，42 号再也长不回来。

新建时选汉字库还是拉丁库（一字一格 vs 各带字宽绕基线），这个选择写进文件的 `mode`。
两套排版的支点不一样、线宽也不是一个数，所以**不做中英混排** ——
真要混，两份工程各导一段，在设计稿里拼。

行预览永远等于你画的顺序。重复的字就画两遍，左栏用 `#2` 区分。

## 产物规格

画布内部单字使用 `viewBox 0 0 64 64`（一字一格）· `fill="none"` ·
`stroke-width 2.8` · `round` cap + join。浏览器内部预览可以用 `currentColor`
跟随父元素换色；下载 SVG
会在导出边界把 `stroke` / `fill` 展开成显式颜色，兼容 Figma 等导入器。单字 SVG
沿用整段导出的「根 Frame + 单字 `<g>`」层级，导入 Figma 后可直接选中字形 Group，
编辑整体线宽和颜色，不需要取消组合；每一笔仍保留为独立 Vector，PNG 也保留逐笔线重，
亮暗主题不需要两份 SVG。

**尺寸下限 44px。** 汉字的笔画密度摆在那儿 —— 「露」有 20 多笔挤在同一个格子里，
30px 起复杂字开始糊。用在正文尺寸上就别用这支笔。

## 性能

单字 0.8ms，14 个字一行 13ms（M 系列 / Chromium 实测）。比原来那趟 localhost 往返还快，
所以没有放进 Web Worker。真要批量生成几百个字再说 —— `src/lib/core` 不碰 DOM，
整个搬进 worker 不用改一行。
