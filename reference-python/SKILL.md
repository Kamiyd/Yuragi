# 手写字

**手感不是画出来的，是过滤出来的。**

这是整套风格唯一的秘密。骨架按规规矩矩的样子画 —— 横是平的、竖是直的、
折角是尖的 —— 然后统一过一遍抖动滤镜。所以：

> 不要凭感觉去「画歪」一笔。你仿不像，而且每加一个字就飘一点，
> 十个字之后是十只手。

还有一条同样要紧的，是这套东西跟排字最根本的分别：

> **画骨架，不画轮廓。** 每一笔是一条**中心线**，粗细交给 `stroke-width`。
> 去描字的外框，描出来是「字的形状」，不是「写出来的字」。

---

## 第 0 步：选轨道

```bash
python3 --version    # 跑得通 → A 轨；跑不通 → B 轨
```

| | **A 轨（首选）** | **B 轨（兜底）** |
|---|---|---|
| 条件 | 能执行命令 | 只能输出文本（网页版对话、Artifact 内） |
| 做法 | 写骨架 JSON → 跑 `scripts/handdraw.py` | 按下面的「路径习语」手写 SVG |
| 手感 | 真滤镜，一整行绝对同一支笔 | 约 80%，同一行里会轻微飘 |

**能跑就跑 A 轨。** 一个字也值得跑 —— 它决定了下一个字跟这个是不是同一只手。

## 已经有字库时：直接排

**这套工具不自带任何字体。** `assets/glyphs.json` 是一份空模板，字是每次自己
画进去的（下面「要画新字」）。手上已有一份攒好的字库时，里面有的字不用重画，
一条命令：

```bash
python3 scripts/handdraw.py write my-font.json "今天好心情" -o title.svg
python3 scripts/handdraw.py write my-font.json "天天开心/好久不见"   # / 断行
python3 scripts/handdraw.py write my-font.json "今天好心情" -s 42     # 固定某一版
python3 scripts/handdraw.py write my-font.json "今天好心情" --no-edit # 只出图，不开编辑器
```

缺字时 `write` 会把缺哪几个列出来，照下面五步补上再排。

**`write` 排完默认把编辑器拉起来**（打印本地链接 + 开浏览器），行预览预填的就是
刚排的这一行和这个种子。**替用户跑的时候一律带 `--no-edit`** —— 不然命令会
挂在服务器上不返回。要人肉看效果、要调字，才让它开。

**每次跑都是新写的一遍**（骨架层重摇：笔画长短、横的高低、撇的斜度）。
满意了就用 `-s` 把那一版钉住。

`write` 自动包办三件手工做不对的事：逐字摇大小（相邻两个字不许一样）、
光学居中、叠字换写法。细节见 `reference/glyphs.md` 的「排一行字」。

## 要画新字：五步

**完整规格在 `reference/glyphs.md`**（64 网格、线重、转折半径、钩怎么甩、
排一行、叠字）。这里只列流程和最容易翻车的地方。

### 1. 先把这个字的印刷体渲出来对着看

**这一步不能跳，包括「这么简单还用看？」的那些。**

> **别凭记忆写骨架。**「业」到底几横、「处」的卜从多高起笔、「膏」下面是月还是日 ——
> 凭印象写十有八九是错的，写错了后面怎么调抖动都救不回来。

系统黑体就够（`PingFang SC` / `STHeiti Medium.ttc`）。跑 `edit` 的话印刷体直接
垫在网格底下，对着描。**但只当结构参照，不要拿它的轮廓当骨架** —— 数一遍横、
数一遍竖、核一遍笔顺，形还是自己重画。

一律**简体**：见/门/画，不是 見/門/畫。

### 2. 拆笔顺，一笔一条 path

按真实笔顺拆。不要把两笔连成一条，也不要把一笔拆成两条 —— 收笔越位是按
「一笔」算的，拆错了两头都会多探出一截。

### 3. 先摆结构，再调细节

左右结构先定分界线（`情` 是 忄 占 8–22、青 占 25–56），上下结构先定横向分界。
**结构错了怎么调笔画都不对。**

### 4. 加手感

```bash
python3 scripts/handdraw.py gallery geo.json -o g.html   # 自检画廊（多尺寸 + 亮暗）
python3 scripts/handdraw.py svg     geo.json -o out/     # 每个字一个 .svg
python3 scripts/handdraw.py json    geo.json             # 路径 JSON
python3 scripts/handdraw.py ts      geo.json             # TS 模块
```

骨架 JSON 长这样（字段全表见 `scripts/handdraw.py` 顶部）：

```json
{"vb": 64, "sw": 2.8, "items": {
  "今": [
    {"t": "path", "d": "M32 12 C27 21 21 28 13 34", "amp": 0.65},
    {"t": "path", "d": "M32 12 C37 21 43 28 51 34", "amp": 0.65},
    {"t": "path", "d": "M27 38 L30 44", "amp": 0.65},
    {"t": "path", "d": "M20 46.5 H40 Q42 46.5 41.6 48.9 L34.5 60.5", "amp": 0.65}
  ]
}}
```

**`"amp": 0.65` 每一笔都要写。** 汉字比图形不经抖，「口」抖散了就不是字了。

**转折必须在路径里自己带半径**，不能指望 `stroke-linejoin: round`：横折走
`Q`（r ≈ 2.5），钩要明显往回上方甩。滤镜在硬角处反而会把抖动压到 0.25 倍，
它救不了你。

### 5. 自检，然后问那一句

把字放在 **88 / 64 / 48 / 44px** 四档并排，亮暗背景各一遍。然后问：

> **它会不会被读成另一个字？**

这是汉字特有的失败模式，比「糊掉」更常见，而且**只有这一步能挡住**。
`reference/glyphs.md` 里有一张实测表（见→兒、天→夭、切→刃、处→永、是→昊），
每一条都写了为什么和怎么修。画完对照着过一遍。

> 放大好看、缩小散架 = 笔画太密或者半径不够。**回第 3 步重摆结构，
> 不要靠调滤镜参数去救** —— 那会把同一套里其余几十个字一起带偏。

## 编辑器

```bash
python3 scripts/handdraw.py edit my-font.json      # 默认 127.0.0.1:8731，-p 换端口
```

文件不存在就自己建一份空库（64 网格，`sw 2.8`，
手感 `amp/jit/vary` 都预设 0.9），点左栏加号先创建未命名的空白字形；输入参考字并保存后才写入字形标题。

**拖的是抖动前的骨架点，看到的是抖动后的线。** 黑体、宋体、楷体都可作为参考底图，
默认黑体；画布下方的单字输入框可输入当前字的参考字，输入法组字期间允许暂存拼音或多个字符，保存时只取第一个字符，
底下一条行预览带逐字大小的相邻差值表。

右栏「整套字的手感」五根滑杆 = 几何 JSON 的字库级字段（`sw` / `amp` / `over` /
`jit` / `vary`，见 `reference/params.md`）—— 拖它们改的是这套字本身，要保存；
下面的显示尺寸、种子、重写开关只是这一次怎么看，不进文件。

渲染和路径读写**全在 Python 那一侧**，浏览器只发骨架点、只收回 path ——
所以不存在「预览跟 `handdraw.py` 出的不是同一条线」。

存盘直接写回同一份几何 JSON，**没拖过的笔画一个字符都不变**。

**它是用来改错的结构的，不是用来攒变体的。** 一个字存一份正确的骨架就够了 ——
「乐」被读成「朱」那类问题必须在这儿改；而「同一个字的第二种写法」不用管，
那是骨架层每次重摇的事（`handdraw.py vary` 可以看变化够不够）。

## B 轨：手写抖动的六条习语

滤镜在做三件事：沿法线叠低频正弦、收笔越位、转角收紧切线。翻译成手写
（数值按 **64 网格**）：

| 滤镜在做什么 | 手写时怎么做 |
|---|---|
| 沿法线叠低频噪声 | 直笔画**不要用 `L`**，用 `C`：中段往法线方向偏 **0.4–0.7**。长笔画偏两次，方向相反 |
| 幅度按弧长分档 | 短笔画（点、短撇，弧长 < 13）偏 **0.25**；中等（13–30）偏 **0.45**；长（> 30）偏 **0.6** |
| 收笔越位 | 每一笔两头各沿切线探出 **0.8–1.4** |
| 转角处压低抖动 | 折角前后各留一小段规矩的直线，别在折角上弯 |
| 折角自带半径 | 横折 `Q`（r ≈ 2.5）；竖钩收笔往回上方甩 4–6 个单位 |
| 逐字不一样 | 一行字**每个字大小差 ±9%**，相邻两个至少差 3.5%，再各自压扁抻长一点 |

最后一条最要紧：**不摇大小就是一版字帖**，线抖得再像也没用。

**A 轨下这张表一条都不用管** —— 骨架画规矩了，滤镜全包。

B 轨额外一条：**一整行一口气画完。** 隔几轮再补的那几个字一定不是同一只手。

## 不可协商的输出规格

```
viewBox        0 0 64 64，一字一格
fill           none
stroke         currentColor      ← 绝不写死 #000 / #fff / 主题色
stroke-width   2.8
linecap        round
linejoin       round
字面落在       7–57，字要撑住格子
尺寸下限       44px
```

`currentColor` 是重点：颜色跟着父元素走，亮暗两套主题**不需要两份 SVG**。

**唯一允许破线重的地方是逐笔提按**（几何里的 `"w"`，范围 0.85–1.15）：
真手写有提按，一个字里横细竖粗是对的。别拿它去救糊掉的字 —— 糊了是结构问题，
加粗只会更糊。

### 不要做的事

- **不拿字体轮廓当骨架**。印刷体只当结构参照，取中线描下来出的是骨架标本
- **不凭记忆写骨架**（见第 1 步，实测翻车最多的一条）
- 不在几何里预先把线画歪 —— 两层抖动会互相打架
- 不手工去改跑出来的坐标：手改的那一笔就永远脱离流水线了，以后动一次滤镜参数，
  别的字跟着变、它不变，一行字里就有两只手
- 不用渐变、阴影、半透明去补救糊掉的字 —— 糊了就回去重摆结构
- 不把这支笔用在正文尺寸上（< 44px）。那个尺寸老老实实排字

## 参考素材

**没有预置字库可抄。** `assets/glyphs.json` 是空模板，这只手长什么样由
`reference/params.md`（滤镜参数）和 `reference/glyphs.md`（骨架规范：网格、
比例、留白、转折半径、钩怎么甩）定死 —— 画新字之前读那两份，不是找个字比着描。

攒到几个字之后，用自己这份库当参照：拿不准折角半径写多少时，
去里面找一个同类折角对齐着写。

看长什么样：`python3 scripts/handdraw.py gallery my-font.json -o ref.html`

## 交付前检查清单

- [ ] 每个新字都**渲了印刷体对着看**吗？横和竖各数了一遍吗？
- [ ] 一律简体吗？（见/门/画，不是 見/門/畫）
- [ ] 笔顺是真实笔顺吗？一笔一条 path，没有连笔也没有拆笔？
- [ ] **每一笔都写了 `"amp": 0.65`** 吗？
- [ ] 每个折角是不是**在路径里**带了半径，而不是只靠 round join？钩甩够了吗？
- [ ] 骨架里的线是**硬的**吗（没有预先画歪）？
- [ ] `fill="none"` + `currentColor` + `stroke-width 2.8`（拉丁 3.4），三样都对？
- [ ] 44px 上还认得出来吗？亮暗背景各看过一遍了吗？
- [ ] **会不会被读成另一个字？**（对照 `glyphs.md` 那张「读成了」表过一遍）
- [ ] 一行字里**每个字不一样大**吗？相邻两个的差值看过没有？
- [ ] 一行字里的叠字，两份几何**真的不一样**吗？（`write` 自动做到；
      手工画的话只换种子不算）
- [ ] 用了 `"w"` 的话，倍率在 0.85–1.15 之间吗？
- [ ] 跑过 `edit` 的话，**保存后的 diff 只落在真正改过的那几笔上**吗？
- [ ] 这一轮踩到的坑，回写进 `reference/glyphs.md` 了吗？

## 这份 skill 是实操里长出来的

每写完一批字，**回来把踩到的坑补进 `reference/glyphs.md`**，不要只改手上那张图：

- 有个字被读成了别的字 → 补进那张「读成了」表，写清楚为什么和怎么修
- 试出来一个更好的画法 → 覆盖掉旧写法，并写清楚**旧写法为什么不够**
  （后来的人才不会改回去）
- 有一条规矩被实践推翻了 → 直接改掉那条规矩，别在旁边加例外

判据：下一次照着这份文档画，会不会再踩一遍同样的坑。会 → 这次的经验没写进来。
